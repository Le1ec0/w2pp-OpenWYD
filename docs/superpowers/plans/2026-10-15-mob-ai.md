**Goal:** Port the common 7.69 generated-monster loop into C#: target acquisition, chase, normal physical attack, leash/return, and party summon aggro propagation.

**Architecture:** Keep deterministic decisions in `WydCdk.World`; let `WorldHub` own locked position, HP, target, and enemy-list mutation. A cancellable `WydCdk.Server` loop processes one source-aligned Peace shard of six and then one Combat shard of four every 200 ms after the host is ready, matching the 7.69 post-initialization cadence. Peace applies passive `Aggro`, route waits/segment changes, route steps for supported non-Clan-4 generated NPCs, and the follower branch for Type 11 `RouteType=5` summons; Combat resolves common chase/leash return and attack. Both stages relay captured views through existing wire messages. Keep the current summon loop as the sole summon attacker.

## Review Focus

- Missing or malformed numeric route fields retain the current catalog contract; segment actions use the first whitespace token, accept at most 78 characters, and preserve the previous value when a repeated value is too long.
- SetBattle applies the inclusive 23-tile rectangle; AddEnemyList skips hidden/merchant only for IDs <=MAX_USER, deduplicates, caps at 13, and leaves Mode=Combat if insertion fails. It does not set CurrentTarget.
- Planner decisions reject invalid, inactive, dead, hidden, and out-of-window targets where the source checks them; merchant filtering is an insertion rule. They retain 7.69 high-level-player behavior and use source-backed clan, special-sector, and Kefra ranges.
- Target selection adds 2 to NPC distance score, skips but does not clear invalid IDs, and resolves equal scores in favor of the last list slot.
- Generated NPC creation passes the catalog RouteType into AI state; RouteType 5 follower behavior follows TMProject even where W2PP differs.
- Passive followers/summons follow their leader or summoner rules instead of entering common-monster target acquisition.
- Direct aggro and both party directions ignore invalid/dead summons, avoid duplicate enemy entries, and are consumed by the same target selector.
- `GetAttack` applies the selector, resistance, Motion, fourth-slot branch, Clan 4 `BaseScore.Special` pair, and specials 121..128. Missing SkillData rows and the normal NPC-target tail remain fail-closed.
- Each nominal 200 ms callback processes one Peace shard (`tick % 6`) before one Combat shard (`tick % 4`), using the legacy `MAX_USER=1000` offset. A Peace NPC is revisited nominally every 1.2 s and a Combat NPC every 800 ms; a mob selected by both in one callback can consume its newly applied aggro in that Combat pass. `PeriodicTimer` waits after processing, so overload can extend both intervals. Stop on cancellation and relay only to recipients captured by the world view.
- The isolated smoke binds and connects only to `IPAddress.Loopback`, confirms both endpoints are loopback, and uses generated fixtures; it does not count as authenticated full-host gameplay or visual `WYD.exe` E2E.
